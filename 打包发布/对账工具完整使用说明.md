## 1. 快速开始

### 前提条件

确保你的电脑上已安装 **Python 3.8+**,然后安装依赖:

```bash
pip install pyzbar opencv-python pandas openpyxl pillow
```

> ⚠️ **注意**: pyzbar 需要 ZBar 底层库支持。如果 `pip install pyzbar` 报错,请访问 http://jaist.dl.sourceforge.net/project/zbar/windows/zbar-0.10.exe 下载安装。

### 启动方式

1. **双击运行** `运行工具.bat`
2. **选择照片文件夹**(包含箱子实拍照片)
3. **选择输出文件夹**(保存对账结果的位置)
4. **等待处理**,完成后自动打开输出文件夹

## 2. 工具介绍

### 核心功能

| 功能 | 说明 |
|------|------|
| 📷 **条码扫描** | 使用 pyzbar 识别照片中的 FBA 编码(如 `FBA19HBZ8XRKU000005`) |
| 📂 **路径推断** | 从文件夹名提取 SKU(如 `SOB001`、`SOK027`) |
| ✅ **对账匹配** | 扫描到的 FBA 编码与第一步汇总表比对 |
| 🔢 **串号检测** | 同一 FBA 箱子出现多个 SKU 自动标记 |
| 📊 **清晰度检测** | 使用 OpenCV Laplacian 算法检测模糊照片 |
| 🗂️ **自动分类** | 根据匹配结果自动生成多个分类 Excel 文件 |

### 工作流程

```
箱子照片 → 扫描FBA条码 → 推断SKU → 与汇总表匹配 → 串号检测 → 生成Excel报告
```

## 5. 输出文件说明

工具会在输出文件夹生成以下文件:

### 5.1 核心文件

| 文件名 | 说明 | 重要程度 |
|--------|------|----------|
| **对账总表_*.xlsx** | 所有照片的完整对账报告 | ⭐⭐⭐ 最重要 |
| **正常匹配_*.xlsx** | 匹配成功且无串号的照片 | ⭐⭐ 正常使用 |
| **模糊照片_*.xlsx** | 照片太模糊无法核对 | ⭐ 需重拍 |

```

```

时间戳格式: `YYYYMMDD_HHMMSS`

## 6. 表格字段详解

### 6.1 对账总表(所有分类文件的汇总)

| 序号 | 字段名 | 说明 | 示例 |
|------|--------|------|------|
| 1 | 原图文件名 | 照片的文件名 | `IMG_20260714_181624.jpg` |
| 2 | 相对路径 | 照片相对于输入文件夹的路径 | `AE/162件/SOB001/IMG_xxx.jpg` |
| 3 | 路径推断SKU | 从文件夹名推断的SKU | `SOB001` 或空 |
| 4 | **扫描FBA编码** | 从照片条码读出的19位FBA编码 | `FBA19HBB4QFKU000005` |
| 5 | **所有扫描条码** | ⭐ 新增:该照片所有条码(分号分隔) | `X003Y6AJ0J; FBA19HBB4QFKU000005` |
| 6 | 扫描条码总数 | 识别到的条码数量 | `2` |
| 7 | 扫描到的标签码 | 亚马逊商品标签码 | `X003Y6AJ0J` |
| 8 | **串号状态** | 🔴 串号 / 🟢 正常无串号 / ⚪ 未知 | `正常无串号` |
| 9 | **匹配状态** | 🔵 匹配成功 / 🟡 模糊 / 🟠 未匹配 / 🔴 无条码 | `✅ 匹配成功` |
| 10 | 图片清晰度 | Laplacian方差评分 | `83.93` |
| 11 | 是否清晰 | 清晰度是否达标 | `是` 或 `否` |
| 12 | 备注 | 附加信息 | 路径中是否有SKU |

### 6.2 字段解读

#### 匹配状态(第9列)

| 状态 | 含义 | 处理方式 |
|------|------|----------|
| ✅ 匹配成功 | FBA编码匹配到汇总表,清晰度达标 | ✅ 正常,无需处理 |
| ⚠️ 有FBA但照片模糊 | 扫到条码但照片模糊 | 📸 重新拍照 |
| ❌ 未识别到FBA条码 | 完全没扫到条码 | 🔍 检查照片是否拍到条码 |
| ⚠️ 扫描到FBA但未匹配到汇总表 | FBA编码不在汇总表中 | ⚠️ 核实是否属于同一批次 |

#### 串号状态(第8列)

| 状态 | 含义 | 风险等级 |
|------|------|----------|
| 正常无串号 | 该箱子只有一个SKU | ✅ 安全 |
| 串号 | 该箱子有多个不同的SKU | 🔴 异常,需人工复核 |
| 未知 | 未进行串号检测(无FBA编码) | ⚪ 暂不判断 |

#### 图片清晰度(第10列)

- **数值**: Laplacian方差,值越大图片越清晰
- **阈值**: 默认15.0,低于此值标记为"模糊"
- **经验值**: 
  - >100: 非常清晰
  - 50-100: 清晰
  - 15-50: 一般
  - <15: 模糊

## 7. 条码识别原理

### 7.1 识别的条码类型

| 类型 | 示例 | 长度 | 用途 |
|------|------|------|------|
| **FBA编码** | `FBA19HBB4QFKU000005` | 19位 | 箱子标识,匹配汇总表 |
| **亚马逊标签码** | `X003Y64QXZ` | 10位 | SKU对应的商品标签 |
| **内部物流码** | `MQGJ2607004191` | 14位 | 仓库内部管理 |

### 7.2 识别流程

```
照片 → 原图扫描(pyzbar) → 识别FBA码 + 标签码
                ↓
         缩放50%后再次扫描
                ↓
         合并去重 → 输出所有条码
```

### 7.3 为什么需要两次扫描?

- **原图扫描**: 适合清晰、近距离拍摄的照片
- **缩放扫描**: 有时缩小图片后,条码线条更粗,反而更容易识别
- **合并去重**: 两次扫描的结果合并,去掉重复项

## 8. 常见问题解答

### Q1: 安装时报错"pyzbar requires ZBar"

**解决方法:**

```bash
# 方法1: conda安装(推荐)
conda install zbar

# 方法2: 下载安装包
# 访问: http://jaist.dl.sourceforge.net/project/zbar/windows/zbar-0.10.exe
# 安装后添加到系统PATH

# 方法3: 使用winget
winget install zbar
```

### Q2: 为什么有些照片扫不出条码?

**可能原因:**
1. 照片太模糊(清晰度<15)
2. 条码被遮挡或损坏
3. 拍照距离太远或角度偏差
4. 光线不好,条码反光
5. 照片上没有贴条码标签

**解决方法:**
- 重新拍摄,保持条码清晰可见
- 调整拍照距离(30-50cm最佳)
- 避免强光和反光

### Q3: 什么是"串号"? 为什么要关注?

**串号定义:**  
一个FBA箱子在汇总表中对应多个不同的SKU编号。

**为什么不正常:**  
正常情况下,一个箱子应该只装一种SKU的产品。如果出现串号,说明:
- 仓库打包时混装了不同产品
- 发货单录入有误
- 需要人工复核确认

**如何处理:**  
打开 `串号_*.xlsx` 文件,检查标记为"串号"的记录,确认是真实串号还是数据错误。

### Q4: 汇总表在哪?如何准备?

汇总表是**第一步工具**(发货单SKU提取工具)的输出文件,位于:
```
汇总结果/发货单_SKU标签汇总_时间戳.xlsx
```

确保:
- 文件命名为 `发货单_SKU标签汇总*.xlsx`
- 放在工具的父目录或上级目录的 `汇总结果` 文件夹中
- 包含 `箱子编码` 和 `SKU号` 列

### Q5: 19位FBA编码格式是什么样的?

标准格式: `FBA + 9位批次号 + 4位流水号 + 6位序列号`

示例:
- `FBA19HBZ8XRK` (12位,无前缀)
- `BS-FBA19HBB4QFKU000005` (22位,带前缀)
- `FBA19HBB4QFKU000005` (19位,完整格式)

**扫描工具识别的是19位格式**(`FBA19HBB4QFKU000005`)。

### Q6: 照片目录结构有要求吗?

**建议结构**(非强制):
```
照片文件夹/
├── 2026.07.14/
│   ├── 发货信息/
│   │   ├── SOB001/
│   │   │   ├── IMG_001.jpg
│   │   │   └── IMG_002.jpg
│   │   └── SOB002/
│   │       └── IMG_003.jpg
```

**好处:**
- 文件夹名中的 `SOB001` 会被自动推断为SKU
- 按日期和组织子文件夹便于管理
- 即使不推断SKU,FBA编码也能正确匹配

**但如果照片直接放在根目录也完全没问题**,只是无法从路径推断SKU。

### Q7: 如何处理大量照片?(几千张)

工具已经优化支持批量处理,建议:
1. 分批处理(每次不超过5000张)
2. 确保内存充足(至少4GB)
3. 处理过程中不要关闭程序
4. 等待进度条完成后再操作

### Q8: 能否修改默认路径?

可以修改代码中的配置区域(第22-24行):

```python
FIRST_STAGE_OUTPUT_FOLDER = r"你的汇总表路径"
DEFAULT_OUTPUT_FOLDER = r"你的输出路径"
CLARITY_THRESHOLD = 15.0  # 清晰度阈值,可调高或调低
```

### Q9: 识别错了怎么办?

1. 打开 `对账总表.xlsx`
2. 查看 `所有扫描条码` 列,确认识别结果
3. 如果是条码质量问题,可以:
   - 重新拍照
   - 在Excel中手动修正匹配状态
   - 人工核对FBA编码是否正确

## 9. 技术架构

### 9.1 技术栈

| 组件 | 技术 | 版本要求 |
|------|------|----------|
| 条码识别 | pyzbar (ZBar库) | >= 0.1.9 |
| 图像处理 | OpenCV | >= 4.8.0 |
| 数据管理 | pandas | >= 2.0.0 |
| Excel导出 | openpyxl | >= 3.1.0 |
| 图片读取 | Pillow | >= 10.0.0 |
| GUI界面 | Tkinter | Python内置 |

### 9.2 核心算法

#### 条码识别
```python
from pyzbar.pyzbar import decode
results = decode(image)
```
使用ZBar库识别二维码和条形码(Code128, Code39, EAN等)。

#### 清晰度检测
```python
import cv2
score = cv2.Laplacian(gray_img, cv2.CV_64F).var()
```
计算图像的Laplacian方差,值越小图像越模糊。

#### 串号检测
```python
all_skus = summary_df[summary_df['箱子编码'] == fba_code]['SKU号'].unique()
if len(all_skus) > 1:
    serial_status = '串号'
```
统计每个FBA编码对应的SKU数量,超过1个即标记为串号。

### 9.3 系统要求

- **操作系统**: Windows 7/8/10/11, macOS 10.14+, Linux
- **Python版本**: 3.8 或更高
- **内存**: 至少 2GB(处理1000张照片)
- **磁盘空间**: 取决于照片数量,每张约1-10MB

## 10. 附录:每个表格的具体用途

### 10.1 对账总表(`对账总表_*.xlsx`)

**用途:** 完整的对账报告,包含所有照片的处理结果

**何时使用:**
- 📊 整体了解处理情况
- 📈 统计分析匹配率、模糊率、串号率
- 🔍 全面检索某张照片的处理结果

**如何浏览:**
- 按"匹配状态"筛选:查看所有"✅ 匹配成功"的照片
- 按"串号状态"筛选:查看"🔴 串号"的异常记录
- 按"图片清晰度"排序:找出最模糊的10张照片

### 10.2 正常匹配(`正常匹配_*.xlsx`)

**用途:** 标记为"✅ 匹配成功"的照片

**何时使用:**
- ✅ 确认哪些箱子是**完全正常**的
- 📦 用于装箱确认、出库审核

**特点:**
- FBA编码匹配到汇总表
- 照片清晰度高
- 无串号问题

### 10.3 模糊照片(`模糊照片_*.xlsx`)

**用途:** 标记为"⚠️ 有FBA但照片模糊"的照片

**何时使用:**
- 📸 需要**重新拍照**的照片清单
- 🎯 质量控制,确保所有照片达标

**处理方法:**
1. 打开该Excel文件
2. 查看"原图文件名"列
3. 找到对应照片,重新拍摄
4. 确保条码清晰可见

### 10.4 无条码(`无条码_*.xlsx`)

**用途:** 标记为"❌ 未识别到FBA条码"的照片

**何时使用:**
- 🔍 检查是否有**漏贴条码**的箱子
- ⚠️ 确认是否是误删的照片

**可能原因:**
- 照片中没有拍到条码
- 条码被遮挡
- 条码损坏无法识别
- 照片拍的是箱子其他面

### 10.5 未匹配FBA(`未匹配FBA_*.xlsx`)

**用途:** 标记为"⚠️ 扫描到FBA但未匹配到汇总表"的照片

**何时使用:**
- ⚠️ 核实是否属于**其他批次**的货物
- 📋 可能需要**补充汇总表数据**

**可能原因:**
- 这批照片是另一批发货的(不在汇总表中)
- FBA编码格式有差异(如带`BS-`前缀)
- 汇总表数据不完整

### 10.6 串号(`串号_*.xlsx`)

**用途:** 标记为"🔴 串号"的照片,同一箱子有多个SKU

**何时使用:**
- 🔴 **重点关注!** 最可能出问题的地方
- ⚠️ 需要人工复核确认

**处理方法:**
1. 打开该Excel文件
2. 查看FBA编码和对应的SKU列表
3. 核对实物:箱子内是否真的混装了多个SKU
4. 如果是真实串号:
   - 分开装箱
   - 修正发货单数据
5. 如果是数据错误:
   - 检查汇总表录入
   - 修正匹配逻辑
